## 범위

다음 영역은 보안 보고의 범위에 포함됩니다:

- **서브프로세스 호출의 명령어 주입**: 셸 명령어에 전달되는 검증되지 않은 입력
- **설정 파일의 자격 증명 노출**: 평문으로 저장된 비밀번호 또는 비밀 정보
- **RDP 세션 하이재킹**: 활성 RDP 세션에 대한 무단 접근
- **UNC 변환의 경로 탐색**: Windows/Linux 경로 변환 조작
- **백엔드 관리를 통한 권한 상승**: 컨테이너 또는 VM 백엔드를 통한 무단 권한 획득

## 보안 모범 사례

이 프로젝트는 다음 보안 관행을 따릅니다:

- **서브프로세스 인자에 대한 입력 검증**: 서브프로세스 호출에 전달되는 모든 인자는 검증 및 정제됩니다
- **평문 비밀번호보다 askpass 우선**: 비밀번호를 평문으로 저장하는 대신 대화형 비밀번호 프롬프트(askpass)를 사용합니다
- **XDG 준수 파일 권한**: 설정 파일은 적절한 파일 권한과 함께 XDG Base Directory 사양을 따릅니다
- **코드나 git에 비밀 정보 없음**: 비밀 정보, 자격 증명, API 키는 저장소에 절대 커밋하지 않습니다
- **TLS 전용 RDP**: SecurityLayer=2 (TLS) RDP 채널 암호화 적용; NLA는 127.0.0.1 바인딩 환경에서만 비활성화
- **Windows 빌드 고정**: 레지스트리 정책으로 Feature update 차단; 보안 업데이트는 정상 설치
- **컨테이너 격리 RDP**: RDP 포트는 127.0.0.1에만 바인딩, 네트워크에 노출되지 않음

## PCI/VFIO 패스스루(선택 기능)

PCI 패스스루는 기본적으로 비활성화되어 있으며, 장치를 명시적으로 할당한 뒤 CLI의
`--force` 옵션이나 GUI 확인을 거쳐야 합니다. 이 기능을 켜는 것은 일반적인 컨테이너
격리 정책에 대한 의도적인 예외입니다.

- VFIO는 IOMMU 그룹 단위로 하드웨어를 격리합니다. Windows에는 QEMU에 선택한 PCI
  function만 보이지만, 컨테이너에는 그룹의 `/dev/vfio/<group>` 파일 디스크립터가
  제공됩니다. 따라서 같은 그룹의 모든 형제 장치는 호스트 드라이버에서 분리하고
  동일한 신뢰 경계에 포함된 것으로 취급해야 하며, QEMU나 컨테이너가 침해되면 그룹
  전체가 영향을 받을 수 있습니다.
- 패스스루 장치는 게스트에 매핑된 메모리로 DMA를 수행할 수 있습니다. 격리는 rootless
  컨테이너 사용자 네임스페이스만이 아니라 호스트 IOMMU(Intel VT-d 또는 AMD-Vi)가
  올바르게 활성화되어 있어야 보장됩니다.
- SELinux 호스트에서 raw USB 또는 PCI 장치에 접근하려면 Windows 컨테이너에
  `label=disable`이 필요합니다. WinPodX는 패스스루 장치 경로가 노출되는 동안에만 이
  옵션을 생성하며, USB live access를 끄고 모든 PCI 할당을 제거하면 일반 컨테이너
  레이블이 복원됩니다.
- rootless Podman은 호스트 장치 권한을 우회하지 않습니다. VFIO 그룹 노드는 보통 root
  소유이므로, 운영자가 ACL 또는 udev 규칙으로 사용자에게 접근 권한을 부여해야 합니다.

WinPodX는 pod 설정 생성 단계에서 fail-closed로 동작합니다. 할당된 모든 PCI 장치는
ASCII 숫자로만 된 IOMMU 그룹으로 확인되어야 하며, 그룹이 없거나 형식이 잘못되면
`/dev/vfio/<group>` 경로나 사용 가능한 compose 설정을 만들기 전에 거부합니다.
